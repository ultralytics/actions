# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, etc.) when working with code in this repository. CLAUDE.md is a symlink to this file.

Ultralytics Actions (`ultralytics-actions` on PyPI, AGPL-3.0) is the GitHub automation toolkit used across the Ultralytics organization: it formats code and documentation, auto-labels issues and PRs, generates AI PR summaries and reviews, and ships supporting composite actions for CI retries, disk cleanup, Dependabot updates, and GitHub reporting. The version lives in `actions/__init__.py` (`__version__`); the supported floor is Python>=3.8 with only `requests` and `ruff` as runtime dependencies. The repo is two things at once: a Python package (`actions/`, CLI entry points in `pyproject.toml` `[project.scripts]`) and GitHub composite actions (the root `action.yml` plus `cla/`, `cleanup-disk/`, `dependabot/`, `github-report/`, `retry/`, `setup-uv/`).

## Core Principles (CRITICAL)

**Less is more. The simplest solution is the best solution.** The action hierarchy for every change: **Delete > Replace > Add**.

1. **Solve at the owner**: Put behavior in the code path that owns or observes it. For fixes, never guard a symptom with a staleness check, initialization flag, skip-first-call branch, or `try/except` around broken logic; relocate the trigger and delete the wrong path. For features, extend the existing owner rather than creating a parallel abstraction.
2. **Search and reuse first**: Search the whole repository before creating a feature, component, helper, workflow, or utility. Reuse or adapt what exists, consolidate in-scope duplication in the shared owner, and delete duplicate paths. Three similar lines beat a helper nobody else calls.
3. **Delete and modify existing code before creating new code**: Bugfixes are net-negative by default unless deletion and relocation are demonstrably impossible. A new file must first prove it cannot fit cleanly in an existing owner.
4. **Keep scope minimal**: Implement only the simplest complete solution. Avoid impossible-state handling, speculative flags, compatibility shims, policy scaffolding, and unrelated cleanup. Tests are out of scope by default — rely on existing coverage and focused validation; only an uncovered, high-risk regression path justifies minimal new test code.
5. **Ship zero-regression, production-ready changes**: Understand what you remove instead of retaining broken code as insurance. Remove unused imports, functions, types, files, and comments; run relevant cleanup checks; and thoroughly debug and validate the changed owner. Do not break existing features or workflows unless the PR intentionally removes them with evidence.

**Review gate:** for every addition, the reviewer decides whether deleting or changing existing code would have fixed the problem instead — if it would, that is a blocking finding. A missing or thin PR description is never itself a finding.

NEVER push to `main`. NEVER force push. Always start work in a new git worktree (`git worktree add`) on a feature branch and open a PR — never edit the primary checkout directly, it may hold in-flight work.

## PR Workflow

After opening a PR:

1. Wait for the automated PR review and auto-format commit from Ultralytics Actions (`format.yml`), then pull and address every finding.
2. Review the full diff in-session against the Core Principles, performance, and the review gate above, then batch the fixes into one commit and push. After each round of bot or human commits, pull and resume the same reviewer on `<last-reviewed-sha>..HEAD` plus anything that delta could have invalidated. Repeat until the local head matches the live head.
3. Hand off or merge only on a clean final pass: one cold full-diff review returning LGTM with no findings, on a head that is still live at merge time.
4. Never fight other commits: Ultralytics Actions pushes auto-format and header commits, and multiple users may work on the same PR. `git pull --rebase` before pushing; never reset or revert commits you did not author.
5. After the PR merges, clean up: remove local worktrees and branches for it, then `git checkout main && git pull`.

## Where to look

Task → owner → existing test. The PR reviewer loads only the first `MAX_CONTEXT_FILE_CHARS` (30,000) characters of this file, so this map stays near the top.

- Formatter output or flags → the step in `action.yml` **and** the mirrored constant in `actions/format_code.py` (`RUFF_CHECK`, `RUFF_FORMAT`, `DOCSTRINGS`, `PRETTIER`, `CODESPELL`); `tests/test_format_code.py` checks each argument is a substring of `action.yml`, so a word appended in `action.yml` alone passes silently — grep both files. Docs-specific prettier rules live in the "Run Prettier" step; codespell words in both `--ignore-words-list`s.
- Auto-format commit missing on a PR → the "Commit and Push Changes" conditions in `action.yml`: same-repo PRs only, `github.actor != inputs.github_username` on `synchronize`, `.github/workflows/` always unstaged.
- Wrong model, provider, price, or prompt guidance → `actions/utils/openai_utils.py` (`*_MODEL_DEFAULT`, `MODEL_COSTS`, `SYSTEM_PROMPT_ADDITION`, `_get_default_model`, `get_review_model`); `README.md`, `README.zh-CN.md`, and the `model`/`review_model` input descriptions in `action.yml` repeat the defaults and are updated by hand (`tests/test_openai_utils.py::test_default_models` pins the constants only).
- PR review skipped, wrong verdict, or missing inline comments → `actions/review_pr.py`: `main` gating, `post_review_summary` (APPROVE vs COMMENT), the comment validation block in `generate_pr_review`, `parse_diff_files` for R/L line numbers; prompt text is inline in `generate_pr_review`; tools in `build_review_agent_tools`. Tests: `tests/test_first_interaction.py` (there is no `test_review_pr.py`).
- Review repeats or reverses findings across pushes → `clear_previous_review`, `_build_review_history`, `_format_review_history`, the `MAX_HISTORY_*` budgets.
- PR summary/labels/welcome comment on open → `actions/first_interaction.py` `main` and `actions/utils/openai_utils.py` `get_pr_open_response`; on close/merge → `actions/summarize_pr.py`; issue/discussion replies → `get_first_interaction_response`; label filtering → `filter_labels`.
- Files wrongly kept in or dropped from AI diffs → `SKIP_PATTERN_STRINGS`/`should_skip_file`/`filter_diff_text` in `actions/utils/common_utils.py` (also gate the review `read_file`/`list_files` tools).
- Broken-link false positives in AI replies → `URL_IGNORE_LIST`, `URL_ERROR_LIST`, `REDIRECT_START_IGNORE_LIST`/`REDIRECT_END_IGNORE_LIST`, `BAD_HTTP_CODES`, `is_url` in `common_utils.py`; tests in `tests/test_urls.py`. The lychee step in `action.yml` is a separate checker for repository Markdown/HTML.
- Header missing or applied to the wrong file → `COMMENT_MAP`, `IGNORE_PATHS` (substring match), and the repo/`HEADER` gate in `actions/update_file_headers.py` `main`; tests in `tests/test_update_file_headers.py`.
- Markdown code block or table formatting → `actions/update_markdown_code_blocks.py` (`extract_code_blocks`, `format_code_with_ruff`, `format_bash_with_shfmt`, `format_markdown_tables`); docstrings → `actions/format_python_docstrings.py` (`format_docstring`, tests in `tests/test_cli_commands.py`).
- GitHub API behavior, retries, pagination → `Action` in `actions/utils/github_utils.py`; tests in `tests/test_github_utils.py`.
- Release not published → `should_publish` in `actions/utils/version_utils.py` (tested in `tests/test_github_utils.py`), the actor gate in `.github/workflows/publish.yml`, and note that job runs the PyPI-installed package.
- CLA check → `actions/cla.py` + `cla/action.yml`; tests in `tests/test_cla.py`. Org reports and auto-merge → `actions/github_report.py` + `actions/failed_scheduled_actions.py`; tests in `tests/test_github_report.py`. Cross-repo action bumps → `actions/dependabot.py` (no tests).
- Adding a CLI command → module `main()`/`run()`, a `[project.scripts]` line in `pyproject.toml`, the `action.yml` step that invokes it with its env vars, and `tests/test_init.py::test_cli_entry_points` if it should be pinned.
- Adding a shared utility → the owning `actions/utils/*.py`, exported from `actions/utils/__init__.py` (`__all__`) only if other modules import it from `actions.utils`.
- Adding a composite action → `<name>/action.yml` + `<name>/README.md` + a usage snippet in `README.md`; copy the install pattern from `dependabot/action.yml` (`setup-uv`, wheel build of `${{ github.action_path }}/..`).

```bash
# Lint/format — mirrors the "Run Python" step in action.yml (source of truth if these drift)
ruff check --fix --unsafe-fixes --extend-select F,I,D,UP,RUF,FA --target-version py38 \
  --ignore BLE001,D100,D104,D203,D205,D212,D213,D401,D406,D407,D413,RUF001,RUF002,RUF012,S110 .
ruff format --line-length 120 .
ultralytics-actions-format-python-docstrings . # Google-style docstring formatter; add --check for a dry run

# Whole formatter pipeline as one CLI (RUFF_CHECK/RUFF_FORMAT/DOCSTRINGS/PRETTIER/CODESPELL from actions/format_code.py)
INPUTS_PRETTIER=false INPUTS_SPELLING=false ultralytics-actions-format # INPUTS_* flags default to true

ultralytics-actions-info # print the GitHub Actions event context the package sees (CI smoke test)
```

- Run pytest from the repository root. `tests/test_update_markdown_codeblocks.py::test_main_real_files` runs the real Markdown formatter over the cwd (it can rewrite `*.md` files; check `git status` afterwards) and `tests/test_first_interaction.py` creates and commits a temporary git repo, so `git` must be on `PATH`. Missing `shfmt` is only logged, so a green suite does not prove every external formatter ran.
- Every `ultralytics-actions-*` command is a `[project.scripts]` entry in `pyproject.toml`; the callable it maps to (module `main()`/`run()`, or `actions.utils:ultralytics_actions_info`) is importable and can be called directly in a Python shell or test.
- Event handlers (`first_interaction`, `review_pr`, `summarize_pr`, `summarize_release`, `update_file_headers`, `dispatch_actions`, `cla`) read `GITHUB_TOKEN`, `GITHUB_EVENT_NAME`, and `GITHUB_EVENT_PATH` (a JSON webhook payload) through `Action()`; to replay one locally, export all three plus `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` for anything that calls a model. `dependabot` builds `Action(token=..., event_data={})`; `github_report` uses the `gh` CLI and `failed_scheduled_actions` uses `urllib` with `GH_TOKEN`/`GITHUB_TOKEN`.
- Code must stay Python 3.8-compatible (CI runs 3.8 and 3.14): use `from __future__ import annotations` for modern hints and avoid 3.9+ methods such as `str.removesuffix`. `check_pypi_version` is the one exception — it imports `tomllib` and needs 3.11+ (its test is skipped below that).
- `pytest` `addopts` in `pyproject.toml` includes `--doctest-modules`, but CI only collects `tests/` and no module under `actions/` contains doctests, so pointing pytest at `actions/` adds nothing.
- `uv.lock` is gitignored; the only tracked lockfile is `actions/cla.py.lock`, the PEP 723 script lock for `actions/cla.py` (regenerate with `uv lock --script actions/cla.py` when its dependency block changes).

## Workflows

All in `.github/workflows/`:

- `ci.yml` (Actions CI) — on PRs, pushes to `main`, and a daily cron. `Test` matrix: ubuntu-latest and macos-latest × Python 3.8 and 3.14 (no Windows pytest job); every job runs the PR's own `./setup-uv`, installs with `uv pip install -e ".[dev]"`, runs `python -m pytest tests -v --cov=actions --cov-report=xml:coverage.xml` through `ultralytics/actions/retry@main` (one retry), then `ultralytics-actions-info`, then uploads to Codecov (`continue-on-error`, no coverage threshold). `Setup-uv-Windows` validates `./setup-uv` Python selection and `.venv` activation on Windows.
- `format.yml` (Ultralytics Actions) — runs `ultralytics/actions@main` (never the PR checkout: this workflow holds write credentials and AI secrets) on `issues: opened` and `pull_request: opened, closed, synchronize, review_requested` with `labels`, `python`, `python_docstrings`, `prettier`, `spelling`, `links`, `summary`, `review` enabled and `openai_api_key` set. Expect an "Auto-format by https://ultralytics.com/actions" commit from `UltralyticsAssistant` on your PR branch, an AI PR summary written into the description, labels, a first-interaction comment, and a "🔍 PR Review" review (numbered from the second review on). PR package changes are exercised by `ci.yml` before merge, not by this workflow.
- `publish.yml` (Publish to PyPI) — on every push to `main` the `deploy-actions` job triggers `deploy_cloud_run.yml` in `ultralytics/assistant`. The `check` job (gated to `github.repository == 'ultralytics/actions'`, `github.actor == 'glenn-jocher'`, ref `main`) installs `ultralytics-actions` **from PyPI** and imports `check_pypi_version` in a `shell: python` step (GitHub runs it as a temp-file script, so the checkout's `actions/` is not on `sys.path` and the PyPI code runs) while the function reads `pyproject.toml` and `actions/__init__.py` from the checkout cwd. `should_publish` accepts a patch bump of 1–2, a new minor `x.(y+1).0`, a new major `(x+1).0.0`, or a package absent from PyPI. On an accepted bump it tags `v<version>`, runs `ultralytics-actions-summarize-release` to create the GitHub release, builds with `python -m build`, publishes via PyPI trusted publishing (one retry), attaches an SPDX SBOM, and notifies Slack. `workflow_dispatch` with `pypi: true` forces a recovery re-run under the same job gate.
- `cla.yml` — `ultralytics/actions/cla@main` on `pull_request_target` and on `issue_comment` whose body equals `recheck` or contains the signing sentence; uses `secrets._GITHUB_TOKEN` as `cla-token`.
- `github_report.yml` — daily 06:00 UTC (and `workflow_dispatch` with `days`), runs `ultralytics/actions/github-report@main` with `visibility: public` and `auto_merge_actions_prs: true`.
- `test-retry.yml` — behavioral tests for the `retry/` action (bash + Python shells, timeouts, backoff timing, invalid inputs) on ubuntu/macos/windows; runs on `workflow_dispatch` and on PRs touching `retry/action.yml` or the workflow itself.
- `.github/dependabot.yml` — weekly updates via three entries across two ecosystems (pip at `/`, GitHub Actions at `/.github/workflows` and at `/`), 3 open PRs max each.

## Conventions

- Ultralytics-owned PyPI packages use `MAJOR.MINOR.PATCH` versions only; no suffixes.
- License headers (`# Ultralytics 🚀 AGPL-3.0 License - https://ultralytics.com/license`) are added automatically by Ultralytics Actions (`ultralytics-actions-headers`, extensions in `COMMENT_MAP`) — don't add or revert them manually.
- Bump `__version__` in `actions/__init__.py` when a PR changes package behavior — publishing to PyPI is gated on the version change (`publish.yml`).
- Google-style docstrings, single-line summaries where possible; formatting is enforced by the repo's own action (`format.yml`), which auto-commits fixes to PRs.
- Tests use `unittest.mock`/`monkeypatch` to patch env vars and network calls; no test reaches the network (`tests/test_urls.py` patches `is_url` with an autouse fixture and calls it with `check=False`). Modules listed in `[tool.coverage.run] omit` are excluded from the coverage report.
- Commits and PRs use plain git identity — no AI attribution, co-author lines, or generated-with footers.

## Architecture

Paths below are relative to the repository root; Python modules live under `actions/`.

**Ownership.** The root `action.yml` owns event/input gating, environment wiring, running external formatters, and committing changes back to the PR. The Python CLI handlers own GitHub automation behavior. `actions/utils/github_utils.py` owns shared GitHub access, `actions/utils/openai_utils.py` owns model calls, `actions/utils/common_utils.py` owns diff filtering and link checking. Standalone composites (`cla/`, `dependabot/`, `github-report/`) have their own install-and-run steps; `retry/` (bash plus a `python3` or PowerShell supervisor), `setup-uv/`, and `cleanup-disk/` (bash) install nothing from this package. A consumer workflow (`format.yml` here, `ultralytics-actions.yml` elsewhere) fires on a GitHub event → the root `action.yml` runs its steps, each gated by `github.event_name`, `github.event.action`, and `inputs.*` → Python-backed steps export env vars (`GITHUB_TOKEN`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `MODEL`, `REVIEW_MODEL`, `LABELS`, `SUMMARY`, `REVIEW`, `HEADER`, ...) and call one CLI entry point → the module's `main()` builds an `Action` from the environment, decides whether to skip (bot author, no API key, wrong event), and works through `Action` REST/GraphQL calls and `get_response`/`get_agent_response`.

### Root `action.yml` (the main action), step by step

- **Install**: `setup-uv` (preceded by `actions/setup-python@v7` only when both `python: true` and a non-empty `python-version` are given), then `uv build --wheel` of the action checkout (`github.action_path`) and `uv pip install --system --break-system-packages` (with `sudo` on Linux), plus `codespell tomli` when `spelling` is on; ends with `ultralytics-actions-info`. Consumers therefore always run the package at the referenced ref, never the PyPI release.
- **Checkout**: only for `pull_request` `opened`/`synchronize`/`review_requested`, at the PR head SHA with `fetch-depth: 2`. The action never checks out code on `pull_request_target`.
- **File Header** (`inputs.header != 'false'`, PR opened/synchronize): `ultralytics-actions-headers` with `HEADER=inputs.header`.
- **Run Python** (`python`): `ruff check --fix --unsafe-fixes ...` then `ruff format --line-length 120`, then `ultralytics-actions-format-python-docstrings .` when `python_docstrings`; every command ends in `|| true`.
- **Run Biome** (`biome`): only if `biome.json`/`biome.jsonc` exists; `npx biome check --write --line-width=120 --max-diagnostics=1000 --diagnostic-level=error --unsafe .`.
- **Run Prettier** (`prettier` or the deprecated `markdown`): installs `prettier@3.8.5` and `shfmt` v3.13.1, runs `ultralytics-actions-update-markdown-code-blocks`, then prettier with `--print-width 120` over `css,less,scss,yml,yaml,html,vue,svelte` (plus `js,jsx,ts,tsx,json` unless Biome owns them), Markdown outside `docs/` at default tab width and `docs/**/*.md` (excluding `reference/`) at `--tab-width 4`, and finally `shfmt -i 2 -sr -bn -ci -l -w` on `*.sh`.
- **Swift** (`swift`, needs a macOS runner) and **Dart** (`dart`: clones Flutter stable through the `retry` action, `flutter pub get` per `pubspec.yaml`, `dart format .`, then `git clean -fdq` and restores `pubspec.lock`).
- **Codespell** (`spelling`): `--builtin clear,informal,en-GB_to_en-US --write-changes`, a camelCase `--ignore-regex`, the `--ignore-words-list`, and a `--skip` list that includes `action.yml` itself.
- **PR Summary** (`summary`, PR `closed`): `ultralytics-actions-summarize-pr`.
- **Bun Update** (`bun_update`, PR `opened`): `bun update --latest` at the root and in `apps/*`/`packages/*`, then `bun update`.
- **Commit and Push Changes**: only for same-repo PRs on `opened`/`synchronize` (on `synchronize` also `github.actor != inputs.github_username`, the recursion guard); `git add .`, then `git reset HEAD -- .github/workflows/` (workflow edits are never committed with the default token), commit as `github_username`/`github_email` (defaults `UltralyticsAssistant`/`web@ultralytics.com`) with message `Auto-format by https://ultralytics.com/actions`, push to the PR head ref.
- **PR Automation and First Interaction**: `ultralytics-actions-first-interaction` when `labels` is on for `opened`/`created`, or for a PR `opened` when `summary` or `review` is on.
- **PR Review**: `ultralytics-actions-review-pr` on `review_requested` when `github.event.requested_reviewer.login == inputs.github_username` (this step does not consult `inputs.review`) — request a review from `UltralyticsAssistant` to re-run the reviewer on demand.
- **Broken Link Checker** (`links`, any PR action but `closed`): downloads the latest `lychee` release for the runner platform (sha256-verified) and checks `./**/*.md` and `./**/*.html` with `--accept 100..=103,200..=299,401,403,429,500,502,999` and an exclude list (github.com, linkedin, twitter, instagram, kaggle, ...).

**Event and flag interactions** (the usual "why didn't it run?" answers):

- Input defaults: `review`, `header`, and `python_docstrings` are `true`; every other feature (`labels`, `python`, `prettier`, `biome`, `swift`, `dart`, `spelling`, `links`, `summary`, `bun_update`) is `false`. `python_docstrings` only runs inside an enabled `python` step.
- On PR `opened`, `first_interaction` generates the summary/labels when `SUMMARY` or `LABELS` is on, posts the fixed welcome comment only when `LABELS` is on, and runs the review only when `REVIEW` is on.
- `synchronize` runs formatting and the header step but never regenerates the summary or review; the review re-runs only via `review_requested` for `UltralyticsAssistant`, the summary only on `closed`.
- YAML gates and Python gates are separate: calling a handler's `main()` directly does not reproduce the `action.yml` conditions, and the Python side adds its own (`should_skip_pr_author`, `should_skip_llm`, PR state, `get_username()` identity checks).

### `actions/utils/` — the shared core

`actions/utils/__init__.py` re-exports a curated subset (`Action`, `GITHUB_API_URL`, `get_response`, `get_agent_response`, `get_review_model`, `filter_labels`, `filter_diff_text`, `should_skip_file`, `check_pypi_version`, ...; see its `__all__`) and the top-level modules import from `actions.utils`; keep `__all__` updated when adding an export. Anything not listed there — `check_links_in_string`, `is_url`, `brave_search`, `should_publish`, `MODEL_COSTS`, the `*_MODEL_DEFAULT` constants, `remove_outer_codeblocks`, `_is_anthropic_model` — is imported from its defining module (`from actions.utils.common_utils import check_links_in_string`, as `first_interaction.py` does).

- **`github_utils.py`** — `Action` is the central abstraction.
  - Construction: `Action(token=None, event_name=None, event_data=None, verbose=True)` falls back to `GITHUB_TOKEN`, `GITHUB_EVENT_NAME`, `GITHUB_EVENT_PATH`; exposes `pr`, `repository`, `owner`, `repo_name`, `headers`, `headers_diff`.
  - Transport: a `requests.Session` mounted with `urllib3.Retry(total=3, backoff_factor=1, status_forcelist=[500, 502, 503, 504], allowed_methods=["GET", "PUT", "DELETE"])`, so connection errors retry on every method but 5xx retries never touch `POST`/`PATCH` (a retried POST could double-post). `_request` (via `get`/`post`/`put`/`patch`/`delete`) sets a default `(10, 60)` timeout (`setdefault`, overridable), prints `✓/✗ METHOD url → status (elapsed)` when verbose, compares the status with `_default_status[method]` or an explicit `expected_status=[...]`, and calls `raise_for_status()` only when `hard=True`; transport exceptions always propagate. `paginate()` walks `per_page=100` pages and raises past ~10,000 items.
  - PR data: `get_pr_diff()` re-fetches the live PR (`hard=True`), diffs `base.sha...head.sha` via the compare API, maps 406 to an "exceeds 20,000 line limit" error string, runs `filter_diff_text`, and caches the `(diff_text, skipped_files)` tuple; `get_pr_head_sha()`, `get_pr_contributors()` (GraphQL credit string), `get_repo_data()`.
  - Identity/gating: `get_username()` (viewer login, cached), `is_org_member()`, `should_skip_pr_author()` (bot or self-authored), `is_fork_pr()`, `should_skip_llm()` (no API key), `is_repo_private()`.
  - Mutations: `update_pr_description()` (replaces everything after `## 🛠️ PR Summary`); `apply_labels`/`add_comment`/`update_content`/`close_item`/`lock_item` (REST for issues/PRs, GraphQL mutations for discussions); `remove_labels` and `block_user` (REST only); `handle_alert()` (rewrites title/body, closes non-PRs, locks, optionally blocks); `create_alert_label()`; `toggle_eyes_reaction()`; `print_info()`.
- **`openai_utils.py`** — provider abstraction over the OpenAI Responses API (`/v1/responses`) and Anthropic Messages API (`/v1/messages`).
  - Env is read **at import time**: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `MODEL`, `REVIEW_MODEL`. `_get_default_model()`: `MODEL` if set, else `ANTHROPIC_MODEL_DEFAULT` when an Anthropic key exists, else `OPENAI_MODEL_DEFAULT`; `get_review_model()`: `REVIEW_MODEL` or the review default of the detected provider; `_is_anthropic_model()` is `model.startswith("claude")`.
  - Single source of truth for `OPENAI_MODEL_DEFAULT`, `ANTHROPIC_MODEL_DEFAULT`, `OPENAI_REVIEW_MODEL_DEFAULT`, `ANTHROPIC_REVIEW_MODEL_DEFAULT`, `MODEL_COSTS` (per-1M-token prices; a model missing here disables `max_cost` budgets and `test_default_models` requires every default to be priced), `MAX_PROMPT_CHARS` (`round(128000 * 3.3 * 0.5)`, a cost ceiling), and `SYSTEM_PROMPT_ADDITION` (branding/tone guidance appended to the leading `system` message when there is one).
  - `get_response(messages, check_links=True, temperature=1.0, text_format=None, model=None, tools=None, retries=2, background=False)` — single-shot call. Retries 5xx/429 and connection errors (`ReadTimeout` deliberately propagates: the request may have completed server-side), polls background/queued OpenAI responses, and for a `json_object`/`json_schema` `text_format` returns decoded JSON **before** any link checking. For Anthropic the schema is appended to the system prompt, `max_tokens=32000`, `temperature` is sent only when not `1.0`, hosted tools are dropped, and a `max_tokens` stop with a schema raises. Plain text goes through `check_links_in_string`; broken URLs are fed back for another attempt (up to `retries` times) and salvaged via redirects/Brave search on the last one.
  - `get_agent_response(messages, tools, tool_handlers, text_format=None, model=None, reasoning_effort=None, max_turns=6, max_cost=0.0, parallel_tools=False, retries=2)` — OpenAI-only tool loop over `previous_response_id`. Handler exceptions become tool-result text so the model can recover; `parallel_tools=True` requires thread-safe handlers; `max_cost` is checked after a response requests tools, so it is a soft cap; after `max_turns` tool turns one forced synthesis turn and one JSON-repair turn may follow. With an Anthropic model it falls back to `get_response` minus function tools.
  - Prompt builders shared by PR open/close: `get_pr_summary_guidelines`, `get_pr_summary_prompt`, `get_pr_open_response` (summary + labels in one JSON call), `filter_labels` (drops manual-only labels, adds `Alert`), `sanitize_ai_text` (strips citation tokens), `remove_outer_codeblocks`.
- **`common_utils.py`** — `SKIP_PATTERN_STRINGS`/`SKIP_PATTERNS`/`should_skip_file`/`filter_diff_text` (lock files, generated dirs, binaries, media, ML weights are removed from diffs and listed via `format_skipped_files_dropdown`/`format_skipped_files_note`), `DIFF_FILE_PATTERN`, `COMMON_EXCLUDED_DIRS`, `remove_html_comments`, `REQUESTS_HEADERS` (browser-like UA), `ACTIONS_CREDIT`, and the link checker: `URL_PATTERN`, `URL_IGNORE_LIST`/`URL_ERROR_LIST`/`REDIRECT_*_IGNORE_LIST`/`BAD_HTTP_CODES`, `is_url` (HEAD then GET with backoff; a failing github.com URL whose repo root returns 404 is treated as possibly private and that root is added to `URL_IGNORE_LIST`), `allow_redirect`, `brave_search` (`BRAVE_API_KEY`), `check_links_in_string(text, return_bad=, replace=)` (64-thread pool).
- **`version_utils.py`** — `should_publish(local, remote)` semver gate, `check_pypi_version()` (reads `pyproject.toml`, follows the dynamic `attr` to `actions/__init__.py`, queries PyPI), `check_pubdev_version()` for Dart packages. Consumed by `publish.yml` here and in other Ultralytics repos.

### Top-level modules (entry point → trigger → behavior)

- `first_interaction.py` (`ultralytics-actions-first-interaction`) — handler for PR `opened`, issue `opened`, and discussion `created`. Env flags become module constants `AUTO_LABELS` (`LABELS`), `AUTO_PR_SUMMARY` (`SUMMARY`), `AUTO_PR_REVIEW` (`REVIEW`, all default true) and `BLOCK_USER` (default false). For a PR (skipping bot/self authors): `get_pr_diff()` → `get_pr_open_response()` → `update_pr_description()` with `SUMMARY_MARKER` + `ACTIONS_CREDIT`, `apply_and_check_labels()` (labels are normalized against the repository's existing labels, so an `Alert` verdict is dropped unless the repo has an `Alert` label; when applied to a non-org member it triggers `handle_alert`), the fixed `get_pr_first_comment_template()` checklist comment, then `review_pr.run_review()` when `AUTO_PR_REVIEW`. For issues/discussions: `get_first_interaction_response()` (labels + a custom first comment in one JSON call, `FIRST_ISSUE_RESPONSE` env overrides the example reply; it link-checks the comment itself because JSON responses skip that step) then label + comment.
- `review_pr.py` (`ultralytics-actions-review-pr`) — `main()`: on a `pull_request` `review_requested` event it returns unless the requested reviewer equals the token's own `get_username()`; skips closed PRs and (unless manually requested) bot/self authors; then `run_review()`: `get_pr_diff()` → `clear_previous_review()` (captures prior bot reviews and replies into a history dict, dismisses their APPROVE/CHANGES_REQUESTED state, deletes their inline comments) → `generate_pr_review()` → `post_review_summary()`.
  - `generate_pr_review` parses the diff with `parse_diff_files()` into `{file: {"RIGHT": {line: text}, "LEFT": {...}, "_HUNK": ...}}` plus an augmented diff whose lines are prefixed `R<n>`/`L<n>`; loads `get_repo_guidelines()` (`CONTRIBUTING.md` plus **one** of `CLAUDE.md`/`AGENTS.md`, Claude models prefer `CLAUDE.md`, each clipped to `MAX_CONTEXT_FILE_CHARS`); `_verified_local_checkout(head_sha)` (`git cat-file -e` on the reviewed commit) decides whether files are read from local git objects or the GitHub contents/trees API.
  - OpenAI review models run `get_agent_response` with `build_review_agent_tools()` (`web_search`, `list_changed_files`, `read_diff`, `read_file`, `list_files`, `search_repo` only with a local checkout, `read_pr_conversation` only when prior reviews exist), `reasoning_effort="high"`, `MAX_AGENT_TURNS`, `REVIEW_COST_SOFT_LIMIT`, `parallel_tools=True`. Anthropic models run single-shot; when at most 10 files changed, each file under 100,000 characters is inlined as a `MAX_CONTEXT_FILE_CHARS` excerpt within the `REVIEW_PROMPT_CHARS` budget.
  - Returned comments are validated against the diff side maps, LEFT-side suggestions and cross-hunk `start_line`s dropped, deduplicated per `file:side:line`, sorted by `SEVERITY_RANK`, capped at `MAX_REVIEW_COMMENTS`. `post_review_summary` posts one review titled `## 🔍 PR Review` (suffixed with the review number from the second review on) with a findings log in the body; it is `APPROVE` only when there was no error, the head did not move, the diff was reviewable and not truncated, and the model produced zero comments before filtering; a 422 on inline anchors re-posts the body alone.
- `summarize_pr.py` (`ultralytics-actions-summarize-pr`) — runs on PR `closed` (it exits on `opened`, which `first_interaction` owns): regenerates the summary from the diff, rewrites the description, and when merged labels closing issues `fixed` with a comment, removes a `TODO` label, and posts a `generate_merge_message()` thank-you crediting `get_pr_contributors()`.
- `summarize_release.py` (`ultralytics-actions-summarize-release`) — needs `CURRENT_TAG` (and optionally `PREVIOUS_TAG`; falls back to `git describe --tags --abbrev=0 --exclude`), diffs the tags, lists merged PRs from commit messages, detects new contributors via the search API, asks the model for a summary, and creates the GitHub release named `<tag> - <last commit subject>`.
- `update_file_headers.py` (`ultralytics-actions-headers`) — walks the cwd for `COMMENT_MAP` extensions, skipping any path containing an `IGNORE_PATHS` substring. Repos under `ultralytics/` get the AGPL header (public) or the `© 2014-<year> Ultralytics Inc. 🚀 All rights reserved. CONFIDENTIAL...` header (private, from `is_repo_private()`); other repos only run when `HEADER` is literal text (not `true`/`false`/`none`). Year ranges are bumped to the current year; existing Ultralytics headers are recognized and replaced, shebangs/encoding cookies/XML declarations preserved.
- `update_markdown_code_blocks.py` (`ultralytics-actions-update-markdown-code-blocks`) — `main()` walks every non-symlink `*.md` under the cwd (no `COMMON_EXCLUDED_DIRS` pruning), extracts fenced `python`/`py`/`{ .py .annotate }` and `bash`/`sh`/`shell` code blocks into `temp_code_blocks/`, formats them with `ruff format`, a looser `ruff check` (extra ignores, no `FA`), the docstring formatter, and `shfmt`, writes them back with original indentation, and aligns pipe tables nested in MkDocs admonitions/tabs (`format_markdown_tables`, skipped for table alignment only under `docs/**/reference/`). Reusable pieces: `process_markdown_string(markdown)` formats fences in a string (it does not call `format_markdown_tables`), `format_markdown_tables(content)`.
- `format_python_docstrings.py` (`ultralytics-actions-format-python-docstrings`) — AST-based Google-style docstring formatter (`format_docstring`, `format_google`, `Visitor`; `format_python_file(text, width=120, start_newline=False)` for a whole source string); leaves numpy/reST/epydoc docstrings and module docstrings alone; CLI flags `--check`, `--start-newline`, `--line-width=N`; uses a `ProcessPoolExecutor` of up to 8 workers.
- `format_code.py` (`ultralytics-actions-format`) — runs the Python/Prettier/Codespell pipeline locally from the `RUFF_CHECK`, `RUFF_FORMAT`, `DOCSTRINGS`, `PRETTIER`, `CODESPELL` constants, gated by `INPUTS_PYTHON`, `INPUTS_PYTHON_DOCSTRINGS`, `INPUTS_PRETTIER`, `INPUTS_SPELLING`. These constants are kept in sync with `action.yml` by hand (see Where to look).
- `cla.py` (no entry point; run by `cla/action.yml` as `uv run --locked --script actions/cla.py` with `PYTHONPATH` set to the action checkout root) — needs `GITHUB_TOKEN` (source repo) and `CLA_TOKEN` (ledger repo); collects the PR opener and every commit author by numeric GitHub user id (bots in `ALLOWLIST` excluded, unlinked commit emails reported as unknown, and it raises if the compare API returns fewer commits than the PR reports), reads the ledger `signatures/version1/cla.json` on the `cla-signatures` branch of `ultralytics/cla`, records comments with a line equal to `SIGN_COMMENT` (case-insensitive, surrounding punctuation/emphasis stripped) into the ledger with optimistic-concurrency `PUT`s, maintains one `<!-- ultralytics-cla -->` status comment, raises when anyone is unsigned, and on `issue_comment` events re-runs the PR-head workflow (needs `GITHUB_WORKFLOW_REF`). Dependencies are the PEP 723 block at the top of the file, locked in `actions/cla.py.lock`.
- `dependabot.py` (`ultralytics-actions-dependabot`; `dependabot/action.yml` runs `python -m actions.dependabot`) — scans every non-archived org repo's `.github/workflows/*.yml|*.yaml` and root `action.yml|action.yaml` for `uses: owner/repo@ref`, resolves each `owner/repo`'s latest stable release once per run (`get_latest_release` caches successes only), updates SHA pins (with a `# vX.Y.Z` comment), major tags, and exact tags via `compute_update`, skips branch refs, and opens one Git-Data-API PR per `(action, new_ref)` on a `dependabot/github_actions/<slug>` branch unless an equivalent title is already open. Env: `GH_TOKEN`/`GITHUB_TOKEN`, `ORG`, `PUBLIC`/`PRIVATE`/`INTERNAL` (all three `false` falls back to scanning all three).
- `github_report.py` (`ultralytics-actions-github-report`; `github-report/action.yml` runs `python -m actions.github_report`) — shells out to the `gh` CLI for repo listing, PR search, and merging. `run_pr_report()` writes the open-PR age report and, when `AUTO_MERGE_ACTIONS_PRS` (default true — set it to `false` to report without merging), `auto_merge_actions_prs()` squash-merges (`--admin --delete-branch`) at most one PR per repo whose title contains `bump` and `/.github/workflows`, whose author is `app/dependabot` or `UltralyticsAssistant`, whose files are all workflow/action files, and whose checks are all `SUCCESS`. Then `failed_scheduled_actions.run()` when `REPORT_FAILED_ACTIONS` (or its deprecated alias `REPORT_FAILED_SCHEDULED_ACTIONS`; the first explicitly set value wins).
- `failed_scheduled_actions.py` (`ultralytics-actions-failed-actions`, alias `ultralytics-actions-failed-scheduled-actions`) — uses `urllib` directly (not `Action`) to find the latest run per workflow on each repo's default branch (at most `MAX_RUN_PAGES` pages, default 3) and report it only when its conclusion is in `FAILED_CONCLUSIONS` and it started within `REPORT_DAYS` (`0` disables the cutoff); a newer success hides an older failure. `parse_visibility` refuses to let a public repo inspect non-public repos.
- `dispatch_actions.py` — handles `issue_comment` PR comments containing `@ultralytics/run-ci`, `@ultralytics/run-all`, or `@ultralytics/run-docker` from org members: dispatches `ci.yml`/`docker.yml` (pushing a `temp-ci-<pr>-<ts>` branch for fork PRs and deleting it afterwards) and rewrites the comment with run links. It has no `[project.scripts]` entry and no `action.yml` step in this repo; nothing but the tests imports it.

### Composite sub-actions

- `retry/action.yml` — inputs `run`, `shell` (bash|python), `retries` (3), `retry_delay_seconds` (10), `backoff` (exponential|fixed), `jitter`, `timeout_minutes` (360). On Linux/macOS a `python3` supervisor runs the script in its own session and kills the process tree on timeout (exit 124; Linux adds a `prctl` child-subreaper plus an env-token scan); Windows uses a PowerShell supervisor. Retries wait with jitter that never rounds a positive delay down to 0. Covered only by `test-retry.yml`, not pytest.
- `setup-uv/action.yml` — wraps `astral-sh/setup-uv@v10.0.0` with `version: latest`, falling back to `latest-known` if that fails; inputs `python-version`, `activate-environment`, `enable-cache`, `cache-dependency-glob`, `ignore-empty-workdir`. The root (after an optional `actions/setup-python@v7` step), `cla/`, `dependabot/`, and `github-report/` actions start with `ultralytics/actions/setup-uv@main`; `retry/` and `cleanup-disk/` never call setup-uv (`retry/` still needs `python3` on Linux/macOS for its timeout supervisor). `ci.yml` exercises `./setup-uv` in every job.
- `cleanup-disk/action.yml` — removes `/opt/hostedtoolcache` and prunes Docker images concurrently, then drops `/swapfile`/`/mnt/swapfile`; no inputs.
- `dependabot/`, `github-report/` — `uv build --wheel` and `uv pip install --system` the package from `${{ github.action_path }}/..` (the action's own checkout), then run `python -m actions.<module>` with inputs mapped to the env vars listed above.
- `cla/` — does not build or install the package wheel: sets `PYTHONPATH` to the action checkout root and runs `uv run --locked --script actions/cla.py`, which provisions only the locked script dependencies (`requests` from the PEP 723 block and `actions/cla.py.lock`) while `actions.utils` is imported from the checkout.

## Gotchas

- Env is read at import time into module constants: `OPENAI_API_KEY`/`ANTHROPIC_API_KEY`/`MODEL`/`REVIEW_MODEL` (`openai_utils.py`), `LABELS`→`AUTO_LABELS`, `SUMMARY`→`AUTO_PR_SUMMARY`, `REVIEW`→`AUTO_PR_REVIEW`, `BLOCK_USER` (`first_interaction.py`), `CURRENT_TAG`/`PREVIOUS_TAG` (`summarize_release.py`), `HEADER` (`update_file_headers.py`). Setting `os.environ` after import has no effect — patch the module attribute (e.g. `patch("actions.utils.openai_utils.OPENAI_API_KEY", "x")`, `patch("actions.first_interaction.AUTO_PR_REVIEW", False)`).
- Patch where the name is looked up. Modules import names into their own namespace (`from .utils import Action, get_response`), so `patch("actions.first_interaction.Action")` and `patch("actions.review_pr.get_agent_response")` work while patching `actions.utils.github_utils.Action` only affects code that resolves the name there (such as `ultralytics_actions_info`).
- `filter_diff_text` runs inside `get_pr_diff()`, so every consumer receives a `(diff_text, skipped_files)` tuple, never a string. `diff_text` may start with `ERROR:` for empty, oversized (406), or failed diffs: `generate_pr_review` branches on that prefix, while the summary prompts interpolate it verbatim; the live PR fetch inside `get_pr_diff()` uses `hard=True` and raises before any tuple exists.
- `generate_pr_review` prints the complete system and user prompts to the job log when `repository == "ultralytics/actions"` — expect very long logs on this repo's own PRs.
- `IGNORE_PATHS` in `update_file_headers.py` is a substring test: entries like `lock`, `env/`, and `build/` skip any path containing them (`.git/` carries a trailing slash so `.github/` is still processed).
- Codespell in `action.yml` skips `action.yml` itself, `*lock*`, `*translat*`, and `docs/??/*.md` translations; a misspelling inside those files is never flagged.
- `_verified_local_checkout` depends only on whether the reviewed commit exists in the runner's git objects, not on the event type. The root `action.yml` checks out the PR head only for `pull_request` events, so under `pull_request_target` the review reads files through the GitHub API and drops the `search_repo` tool unless the consumer workflow checked out that head itself.
- `Action`'s session retries connection failures on every method but 5xx responses only on `GET`/`PUT`/`DELETE`; a `POST`/`PATCH` that returns 5xx is not retried by the session — callers such as `cla._read`/`_persist` and `get_response` implement their own loops.
- `publish.yml`'s `check` job gates releases with the **PyPI-installed** `ultralytics-actions` (`shell: python` temp script plus the `ultralytics-actions-summarize-release` console script, neither of which sees the checkout's `actions/`), so a change to `version_utils.py` or `summarize_release.py` only affects the next release after it is itself published.
- `update_markdown_code_blocks.main()` (and `test_main_real_files`) writes a `temp_code_blocks/` directory in the cwd and deletes it on completion; `format_bash_with_shfmt` only prints an error when `shfmt` is missing locally.
- The `Alert` label path in `apply_and_check_labels` rewrites the title/body, locks, and (for issues/discussions) closes the item for a non-org member as soon as the model returns `Alert` and the repository has that label; `BLOCK_USER=true` additionally blocks the account org-wide.

## Tests

- `tests/` is flat and mostly one file per module, with shared owners: `tests/test_first_interaction.py` also covers `review_pr` (history capture, tool construction against a real temporary git repo, APPROVE/COMMENT decisions); `tests/test_github_report.py` covers `failed_scheduled_actions`; `tests/test_cli_commands.py` holds the `format_python_docstrings` regressions; `tests/test_github_utils.py` holds `test_check_pypi_version`; `tests/test_format_code.py` checks the formatter constants against `action.yml` and that every `run:` step in `action.yml` opens a log group with an `EXIT` trap; `tests/test_init.py` checks the version format, importability, and entry-point names. `actions/dependabot.py` has no tests. Other files map one-to-one: `test_github_utils.py`, `test_openai_utils.py`, `test_common_utils.py`, `test_urls.py`, `test_summarize_pr.py`, `test_summarize_release.py`, `test_update_file_headers.py`, `test_update_markdown_codeblocks.py`, `test_cla.py`, `test_dispatch_actions.py`.
- No shared `conftest.py` or fixtures directory; each file builds `MagicMock` responses/events inline (`tests/test_cla.py` has small `response()`/`action()`/`ledger_response()` helpers worth copying). Network is always mocked (`requests.post`, `requests.Session.get`, `urllib.request.urlopen`, or the module-level function), so the suite needs no tokens or API keys; filesystem and git side effects are real (see Commands).
- CI runs exactly `python -m pytest tests -v --cov=actions --cov-report=xml:coverage.xml` on Python 3.8 and 3.14 on ubuntu and macos; there is no Windows pytest job and no coverage threshold, and `[tool.coverage.run] omit` excludes the review, first-interaction, model, and formatter modules from the report. Composite actions are not covered by pytest: `setup-uv` runs as `./setup-uv` in every `ci.yml` job (including the Windows one), `retry` has `test-retry.yml`, and `cla`, `cleanup-disk`, `dependabot`, and `github-report` are exercised only by the org workflows that consume them.
