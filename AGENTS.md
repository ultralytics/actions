# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, etc.) when working with code in this repository. CLAUDE.md is a symlink to this file.

Ultralytics Actions (`ultralytics-actions` on PyPI, AGPL-3.0) is the GitHub automation toolkit used across the Ultralytics organization: it formats code and documentation, auto-labels issues and PRs, generates AI PR summaries and reviews, and ships supporting composite actions for CI retries, disk cleanup, Dependabot updates, and GitHub reporting. The version lives in `actions/__init__.py` (`__version__`); the supported floor is Python>=3.8 with only `requests` and `ruff` as runtime dependencies.

## Core Principles (CRITICAL)

**Less is more. The simplest solution is the best solution.** The action hierarchy for every change: **Delete > Replace > Add**.

1. **Solve at the owner**: Put behavior in the code path that owns or observes it. For fixes, never guard a symptom with a staleness check, initialization flag, skip-first-call branch, or `try/except` around broken logic; relocate the trigger and delete the wrong path. For features, extend the existing owner rather than creating a parallel abstraction.
2. **Search and reuse first**: Search the whole repository before creating a feature, component, helper, workflow, or utility. Reuse or adapt what exists, consolidate in-scope duplication in the shared owner, and delete duplicate paths. Three similar lines beat a helper nobody else calls.
3. **Delete and modify existing code before creating new code**: Bugfixes are net-negative by default unless deletion and relocation are demonstrably impossible. A new file must first prove it cannot fit cleanly in an existing owner.
4. **Keep scope minimal**: Implement only the simplest complete solution. Avoid impossible-state handling, speculative flags, compatibility shims, policy scaffolding, and unrelated cleanup. Tests are out of scope by default — rely on existing coverage and focused validation; only an uncovered, high-risk regression path justifies minimal new test code.
5. **Ship zero-regression, production-ready changes**: Understand what you remove instead of retaining broken code as insurance. Remove unused imports, functions, types, files, and comments; run relevant cleanup checks; and thoroughly debug and validate the changed owner. Do not break existing features or workflows unless the PR intentionally removes them with evidence.

**Review gate:** for every addition, the reviewer decides whether deleting or changing existing code would have fixed the problem instead — if it would, that is a blocking finding. A missing or thin PR description is never itself a finding.

NEVER push to `main`. NEVER force push. Always start work in a new git worktree (`git worktree add`) on a feature branch and open a PR — never edit the primary checkout directly, it may hold in-flight work.

## PR Workflow

After opening a PR:

1. Wait for the automated PR review and auto-format commit from Ultralytics Actions (`format.yml`), then pull and address every finding.
2. Review the full diff in-session against the Core Principles, performance, and the review gate above, then batch the fixes into one commit and push. After each round of bot or human commits, pull and resume the same reviewer on `<last-reviewed-sha>..HEAD` plus anything that delta could have invalidated. Repeat until the local head matches the live head.
3. Hand off or merge only on a clean final pass: one cold full-diff review returning LGTM with no findings, on a head that is still live at merge time.
4. Never fight other commits: Ultralytics Actions pushes auto-format and header commits, and multiple users may work on the same PR. `git pull --rebase` before pushing; never reset or revert commits you did not author.
5. After the PR merges, clean up: remove local worktrees and branches for it, then `git checkout main && git pull`.

- Every `ultralytics-actions-*` command is a `[project.scripts]` entry in `pyproject.toml`; the module `main()`/`run()` it maps to is importable and can be called directly in a Python shell or test.
- GitHub-facing scripts read `GITHUB_TOKEN`, `GITHUB_EVENT_NAME`, and `GITHUB_EVENT_PATH` (a JSON event payload) through `Action()`; to run one locally, point `GITHUB_EVENT_PATH` at a saved webhook payload and export the token plus `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` for anything that calls a model.
- Code must stay Python 3.8-compatible (CI runs 3.8 and 3.14): use `from __future__ import annotations` for modern hints and avoid 3.9+ methods such as `str.removesuffix`. `check_pypi_version` is the one exception — it imports `tomllib` and needs 3.11+ (its test is skipped below that).
- `pytest` `addopts` in `pyproject.toml` includes `--doctest-modules`, but CI only collects `tests/` and no module under `actions/` contains doctests, so pointing pytest at `actions/` adds nothing.
- `uv.lock` is gitignored; the only tracked lockfile is `actions/cla.py.lock`, the PEP 723 script lock for `actions/cla.py`.

## Workflows

All in `.github/workflows/`:

- `ci.yml` (Actions CI) — on PRs, pushes to `main`, and a daily cron. `Test` matrix: ubuntu-latest and macos-latest × Python 3.8 and 3.14 (Windows is excluded from the test matrix); installs with `uv pip install -e ".[dev]"`, runs `python -m pytest tests -v --cov=actions --cov-report=xml:coverage.xml` through `ultralytics/actions/retry@main` (one retry), then `ultralytics-actions-info`, then uploads to Codecov (`continue-on-error`, no coverage threshold). A separate `Setup-uv-Windows` job only validates `./setup-uv` on Windows.
- `format.yml` (Ultralytics Actions) — runs `ultralytics/actions@main` (never the PR checkout: this workflow holds write credentials and AI secrets) on `issues: opened` and `pull_request: opened, closed, synchronize, review_requested` with `labels`, `python`, `python_docstrings`, `prettier`, `spelling`, `links`, `summary`, `review` enabled and `openai_api_key` set. Expect an "Auto-format by https://ultralytics.com/actions" commit from `UltralyticsAssistant` on your PR branch, an AI PR summary written into the description, labels, a first-interaction comment, and a numbered "🔍 PR Review" review. PR package changes are exercised by `ci.yml` before merge, not by this workflow.
- `publish.yml` (Publish to PyPI) — on every push to `main` the `deploy-actions` job triggers `deploy_cloud_run.yml` in `ultralytics/assistant`. The `check` job (gated to `github.actor == 'glenn-jocher'`) installs `ultralytics-actions` **from PyPI** and calls its `check_pypi_version()`, which reads the checkout's `actions/__init__.py`; `should_publish` accepts only a patch bump of 1–2, a new minor `x.(y+1).0`, or a new major `(x+1).0.0`. On an accepted bump it tags `v<version>`, runs `ultralytics-actions-summarize-release` to create the GitHub release, builds with `python -m build`, publishes via PyPI trusted publishing (one retry), attaches an SPDX SBOM, and notifies Slack. `workflow_dispatch` with `pypi: true` forces a recovery re-run.
- `cla.yml` — `ultralytics/actions/cla@main` on `pull_request_target` and on `issue_comment` containing `recheck` or the signing sentence; uses `secrets._GITHUB_TOKEN` as `cla-token`.
- `github_report.yml` — daily 06:00 UTC (and `workflow_dispatch` with `days`), runs `ultralytics/actions/github-report@main` with `visibility: public` and `auto_merge_actions_prs: true`.
- `test-retry.yml` — runs the `retry/` action's behavioral tests (bash + Python shells, timeouts, backoff timing, invalid inputs) on ubuntu/macos/windows, only when `retry/action.yml` or the workflow itself changes.
- `.github/dependabot.yml` — weekly pip and GitHub Actions updates, 3 open PRs max each.

## Conventions

- Ultralytics-owned PyPI packages use `MAJOR.MINOR.PATCH` versions only; no suffixes.
- License headers (`# Ultralytics 🚀 AGPL-3.0 License - https://ultralytics.com/license`) are added automatically by Ultralytics Actions (`ultralytics-actions-headers`, extensions in `COMMENT_MAP`) — don't add or revert them manually.
- Bump `__version__` in `actions/__init__.py` when a PR changes package behavior — publishing to PyPI is gated on the version change (`publish.yml`).
- Google-style docstrings, single-line summaries where possible; formatting is enforced by the repo's own action (`format.yml`), which auto-commits fixes to PRs.
- Tests use `unittest.mock`/`monkeypatch` to patch env vars and network calls; the whole suite runs offline (`tests/test_urls.py` patches `is_url` with an autouse fixture and calls it with `check=False`). Modules listed in `[tool.coverage.run] omit` are excluded from the coverage report.
- Commits and PRs use plain git identity — no AI attribution, co-author lines, or generated-with footers.

## Architecture

Paths below are relative to the repository root; Python modules live under `actions/`.

This repo is two things at once:

1. **A Python package (`actions/`)** published as `ultralytics-actions` on PyPI. Top-level modules are standalone scripts, most exposed as `ultralytics-actions-*` CLI entry points in `pyproject.toml` `[project.scripts]`.
2. **GitHub composite actions.** The root `action.yml` is the main "Ultralytics Actions" marketplace action; `cla/`, `cleanup-disk/`, `dependabot/`, `github-report/`, `retry/`, and `setup-uv/` are standalone composite actions, each with its own `action.yml` + README.

**Request flow.** A consumer workflow (`format.yml` here, `ultralytics-actions.yml` elsewhere) fires on a GitHub event → the root `action.yml` runs its steps, each gated by `github.event_name`, `github.event.action`, and the `inputs.*` flags → each step exports env vars (`GITHUB_TOKEN`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `MODEL`, `REVIEW_MODEL`, `LABELS`, `SUMMARY`, `REVIEW`, `HEADER`, ...) and calls one CLI entry point → the module's `main()` builds an `Action` from the environment, decides whether to skip (bot author, no API key, wrong event), and does its work through `Action` REST/GraphQL calls and `get_response`/`get_agent_response`.

### Root `action.yml` (the main action), step by step

- **Install**: `setup-uv`, then `uv build --wheel` of the action checkout (`github.action_path`) and `uv pip install --system --break-system-packages` (with `sudo` on Linux), plus `codespell tomli` when `spelling` is on; ends with `ultralytics-actions-info`. Consumers therefore always run the package at the referenced ref, never the PyPI release.
- **Checkout**: only for `pull_request` `opened`/`synchronize`/`review_requested`, at the PR head SHA with `fetch-depth: 2`. `pull_request_target` events never check out code, so downstream tools fall back to the GitHub API (see review below).
- **File Header** (`inputs.header != 'false'`, PR opened/synchronize): `ultralytics-actions-headers` with `HEADER=inputs.header`.
- **Run Python** (`python`): `ruff check --fix --unsafe-fixes ...` then `ruff format --line-length 120`, then `ultralytics-actions-format-python-docstrings .` when `python_docstrings`; every command ends in `|| true`.
- **Run Biome** (`biome`): only if `biome.json`/`biome.jsonc` exists; `npx biome check --write --line-width=120 --max-diagnostics=1000 --diagnostic-level=error --unsafe .`.
- **Run Prettier** (`prettier` or the deprecated `markdown`): installs `prettier@3.8.5` and `shfmt` v3.13.1, runs `ultralytics-actions-update-markdown-code-blocks`, then prettier with `--print-width 120` over `css,less,scss,yml,yaml,html,vue,svelte` (plus `js,jsx,ts,tsx,json` unless Biome owns them), Markdown outside `docs/` at default tab width and `docs/**/*.md` (excluding `reference/`) at `--tab-width 4`, and finally `shfmt -i 2 -sr -bn -ci -l -w` on `*.sh`.
- **Swift** (`swift`, needs a macOS runner) and **Dart** (`dart`: clones Flutter stable through the `retry` action, `flutter pub get` per `pubspec.yaml`, `dart format .`, then `git clean -fdq` and restores `pubspec.lock`).
- **Codespell** (`spelling`): `--builtin clear,informal,en-GB_to_en-US --write-changes`, a camelCase `--ignore-regex`, the `--ignore-words-list`, and a `--skip` list that includes `action.yml` itself.
- **PR Summary** (`summary`, PR `closed`): `ultralytics-actions-summarize-pr`.
- **Bun Update** (`bun_update`, PR `opened`): `bun update --latest` at the root and in `apps/*`/`packages/*`, then `bun update`.
- **Commit and Push Changes**: only for same-repo PRs on `opened`/`synchronize` (on `synchronize` also `github.actor != inputs.github_username`, the recursion guard); `git add .`, then `git reset HEAD -- .github/workflows/` (workflow edits are never committed with the default token), commit as `github_username`/`github_email` (defaults `UltralyticsAssistant`/`web@ultralytics.com`) with message `Auto-format by https://ultralytics.com/actions`, push to the PR head ref.
- **PR Automation and First Interaction**: `ultralytics-actions-first-interaction` when `labels` is on for `opened`/`created`, or for a PR `opened` when `summary` or `review` is on.
- **PR Review**: `ultralytics-actions-review-pr` on `review_requested` when `github.event.requested_reviewer.login == inputs.github_username` — request a review from `UltralyticsAssistant` to re-run the reviewer on demand.
- **Broken Link Checker** (`links`, any PR action but `closed`): downloads the latest `lychee` release for the runner platform (sha256-verified) and checks `./**/*.md` and `./**/*.html` with `--accept 100..=103,200..=299,401,403,429,500,502,999` and an exclude list (github.com, linkedin, twitter, instagram, kaggle, ...).

### `actions/utils/` — the shared core

Everything here is re-exported through `actions/utils/__init__.py`; keep `__all__` updated when adding exports (tests import from `actions.utils`).

- **`github_utils.py`** — `Action` is the central abstraction. `__init__` reads `GITHUB_TOKEN`, `GITHUB_EVENT_NAME`, `GITHUB_EVENT_PATH` (or accepts `token=`, `event_name=`, `event_data=`, `verbose=`), exposes `pr`, `repository`, `owner`, `repo_name`, and mounts a `requests.Session` with `urllib3.Retry(total=3, backoff_factor=1, status_forcelist=[500, 502, 503, 504], allowed_methods=["GET", "PUT", "DELETE"])` so a retried POST can never double-post. `_request` (via `get`/`post`/`put`/`patch`/`delete`) applies a `(10, 60)` timeout, prints `✓/✗ METHOD url → status (elapsed)` when verbose, checks the status against `_default_status[method]` or an explicit `expected_status=[...]`, and only raises when `hard=True`. `paginate()` walks `per_page=100` pages (10,000-item cap). Higher-level: `get_pr_diff()` re-fetches the live PR, diffs `base.sha...head.sha` via the compare API, maps 406 to a "exceeds 20,000 line limit" error string, runs `filter_diff_text`, and caches the `(diff, skipped_files)` tuple; `get_pr_head_sha()`, `get_username()` (viewer login, cached), `is_org_member()`, `should_skip_pr_author()` (bot or self-authored), `is_fork_pr()`, `should_skip_llm()` (no API key), `update_pr_description()` (replaces everything after `## 🛠️ PR Summary`), `apply_labels`/`remove_labels`/`add_comment`/`update_content`/`close_item`/`lock_item` (REST for issues/PRs, GraphQL for discussions), `handle_alert()` (rewrites, locks, closes non-PRs, optionally `block_user`), `get_pr_contributors()` (GraphQL credit string), `toggle_eyes_reaction()`, `print_info()`.
- **`openai_utils.py`** — provider abstraction over the OpenAI Responses API (`/v1/responses`) and Anthropic Messages API (`/v1/messages`). `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `MODEL`, `REVIEW_MODEL` are read **at import time**. `_get_default_model()`: `MODEL` if set, else `ANTHROPIC_MODEL_DEFAULT` when an Anthropic key exists, else `OPENAI_MODEL_DEFAULT`; `get_review_model()`: `REVIEW_MODEL` or the review default of the detected provider; `_is_anthropic_model()` is `model.startswith("claude")`. Single source of truth for `OPENAI_MODEL_DEFAULT`, `ANTHROPIC_MODEL_DEFAULT`, `OPENAI_REVIEW_MODEL_DEFAULT`, `ANTHROPIC_REVIEW_MODEL_DEFAULT`, `MODEL_COSTS` (per-1M-token prices; a model missing here disables `max_cost` budgets and `test_default_models` requires every default to be priced), `MAX_PROMPT_CHARS` (`round(128000 * 3.3 * 0.5)`, a cost ceiling), and `SYSTEM_PROMPT_ADDITION` (branding/tone guidance appended to every system message). `get_response(messages, ...)` is the single-shot call: retries 5xx/429 and connection errors, polls background/queued OpenAI responses, parses `text_format` JSON schema output (for Anthropic the schema is appended to the system prompt, `max_tokens=32000`, hosted tools are dropped), and on plain text runs `check_links_in_string` and re-prompts once with the broken URLs before salvaging via redirects/Brave search. `get_agent_response(messages, tools, tool_handlers, ...)` is the OpenAI-only tool loop (`previous_response_id` continuation, `max_turns`, `max_cost`, optional `parallel_tools`, forced synthesis turn, one JSON repair turn); with an Anthropic model it falls back to `get_response` minus function tools. Prompt builders shared by PR open/close: `get_pr_summary_guidelines`, `get_pr_summary_prompt`, `get_pr_open_response` (summary + labels in one JSON call), `filter_labels` (drops manual-only labels, adds `Alert`), `sanitize_ai_text` (strips citation tokens), `remove_outer_codeblocks`.
- **`common_utils.py`** — `SKIP_PATTERNS`/`should_skip_file`/`filter_diff_text` (lock files, generated dirs, binaries, media, ML weights are removed from diffs and listed via `format_skipped_files_dropdown`/`format_skipped_files_note`), `DIFF_FILE_PATTERN`, `COMMON_EXCLUDED_DIRS`, `remove_html_comments`, `REQUESTS_HEADERS` (browser-like UA), `ACTIONS_CREDIT`, and the link checker: `URL_PATTERN`, `URL_IGNORE_LIST`/`URL_ERROR_LIST`/`REDIRECT_*_IGNORE_LIST`, `is_url` (HEAD then GET, retries with backoff, adds private GitHub repos to the ignore list), `allow_redirect`, `brave_search` (`BRAVE_API_KEY`), `check_links_in_string(text, return_bad=, replace=)` (64-thread pool).
- **`version_utils.py`** — `should_publish(local, remote)` semver gate, `check_pypi_version()` (reads `pyproject.toml`, follows the dynamic `attr` to `actions/__init__.py`, queries PyPI), `check_pubdev_version()` for Dart packages. Consumed by `publish.yml` here and in other Ultralytics repos.

### Top-level modules (entry point → trigger → behavior)

- `first_interaction.py` (`ultralytics-actions-first-interaction`) — the PR/issue/discussion `opened` handler. Module-level flags from env: `LABELS`, `SUMMARY`, `REVIEW` (default true), `BLOCK_USER` (default false). For a PR `opened` (skipping bot/self authors): `get_pr_diff()` → `get_pr_open_response()` → `update_pr_description()` with `SUMMARY_MARKER` + `ACTIONS_CREDIT`, `apply_and_check_labels()` (an `Alert` label on a non-org member triggers `handle_alert`), the fixed `get_pr_first_comment_template()` checklist comment, then `review_pr.run_review()` when `REVIEW`. For issues/discussions: `get_first_interaction_response()` (labels + a custom first comment in one JSON call, `FIRST_ISSUE_RESPONSE` env overrides the example reply) then label + comment.
- `review_pr.py` (`ultralytics-actions-review-pr`) — `main()` accepts `review_requested` only when the requested reviewer is the bot, skips closed PRs and (unless manually requested) bot/self authors, then `run_review()`: `get_pr_diff()` → `clear_previous_review()` (captures prior bot reviews and replies into a history dict, dismisses their APPROVE/CHANGES_REQUESTED state, deletes their inline comments) → `generate_pr_review()` → `post_review_summary()`. `generate_pr_review` parses the diff with `parse_diff_files()` into `{file: {"RIGHT": {line: text}, "LEFT": {...}, "_HUNK": ...}}` plus an augmented diff whose lines are prefixed `R<n>`/`L<n>`; loads `get_repo_guidelines()` (`CONTRIBUTING.md` plus **one** of `CLAUDE.md`/`AGENTS.md`, Claude models prefer `CLAUDE.md`, each clipped to `MAX_CONTEXT_FILE_CHARS`); with an OpenAI review model it runs `get_agent_response` with `build_review_agent_tools()` (`web_search`, `list_changed_files`, `read_diff`, `read_file`, `list_files`, `search_repo`, `read_pr_conversation`), `reasoning_effort="high"`, `MAX_AGENT_TURNS`, `REVIEW_COST_SOFT_LIMIT`, `parallel_tools=True`; with an Anthropic model it inlines up to 10 full files and runs single-shot. `_verified_local_checkout(head_sha)` decides whether tools read `git cat-file`/`git ls-tree`/`git grep` at the head SHA or the GitHub contents/trees API; `search_repo` exists only with a local checkout, `read_pr_conversation` only when prior reviews exist. Returned comments are validated against the diff side maps, LEFT-side suggestions and cross-hunk `start_line`s dropped, deduplicated per `file:side:line`, sorted by `SEVERITY_RANK`, capped at `MAX_REVIEW_COMMENTS`. `post_review_summary` posts one review titled `## 🔍 PR Review[ N]` with a findings log in the body; it is `APPROVE` only when there was no error, the head did not move, the diff was reviewable and not truncated, and the model produced zero comments (before filtering); a 422 on inline anchors re-posts the body alone.
- `summarize_pr.py` (`ultralytics-actions-summarize-pr`) — runs on PR `closed` (it exits on `opened`, which `first_interaction` owns): regenerates the summary from the diff, rewrites the description, and when merged labels closing issues `fixed` with a comment, removes a `TODO` label, and posts a `generate_merge_message()` thank-you crediting `get_pr_contributors()`.
- `summarize_release.py` (`ultralytics-actions-summarize-release`) — needs `CURRENT_TAG` (and optionally `PREVIOUS_TAG`; falls back to `git describe --tags --abbrev=0 --exclude`), diffs the tags, lists merged PRs from commit messages, detects new contributors via the search API, asks the model for a summary, and creates the GitHub release named `<tag> - <last commit subject>`.
- `update_file_headers.py` (`ultralytics-actions-headers`) — walks the cwd for `COMMENT_MAP` extensions, skipping any path containing an `IGNORE_PATHS` substring. Repos under `ultralytics/` get the AGPL header (public) or the `© 2014-<year> Ultralytics Inc. 🚀 All rights reserved. CONFIDENTIAL...` header (private, from `is_repo_private()`); other repos only run when `HEADER` is literal text (not `true`/`false`/`none`). Year ranges are bumped to the current year; existing Ultralytics headers are recognized and replaced, shebangs/encoding cookies/XML declarations preserved.
- `update_markdown_code_blocks.py` (`ultralytics-actions-update-markdown-code-blocks`) — extracts fenced `python`/`py`/`{ .py .annotate }` and `bash`/`sh`/`shell` code blocks from every non-symlink `*.md` under the cwd into `temp_code_blocks/`, formats them with `ruff format`, a looser `ruff check` (extra ignores, no `FA`), the docstring formatter, and `shfmt`, writes them back with original indentation, and aligns pipe tables nested in MkDocs admonitions/tabs (`format_markdown_tables`, skipped under `docs/**/reference/`).
- `format_python_docstrings.py` (`ultralytics-actions-format-python-docstrings`) — AST-based Google-style docstring formatter (`format_docstring`, `format_google`, `Visitor`); leaves numpy/reST/epydoc docstrings and module docstrings alone; CLI flags `--check`, `--start-newline`, `--line-width=N`; uses a `ProcessPoolExecutor` of up to 8 workers.
- `format_code.py` (`ultralytics-actions-format`) — runs the Python/Prettier/Codespell pipeline locally from the `RUFF_CHECK`, `RUFF_FORMAT`, `DOCSTRINGS`, `PRETTIER`, `CODESPELL` constants, gated by `INPUTS_PYTHON`, `INPUTS_PYTHON_DOCSTRINGS`, `INPUTS_PRETTIER`, `INPUTS_SPELLING`. These constants must be kept in sync with `action.yml` by hand; `tests/test_format_code.py::test_format_commands_match_action_yml` checks each argument is a substring of `action.yml`.
- `cla.py` (no entry point; run by `cla/action.yml` as `uv run --locked --script actions/cla.py` with `PYTHONPATH` set to the repo root) — needs `GITHUB_TOKEN` and `CLA_TOKEN`; collects the PR opener and every commit author (bots in `ALLOWLIST` excluded, unlinked emails reported as unknown), reads the ledger `signatures/version1/cla.json` on the `cla-signatures` branch of `ultralytics/cla`, records comments with a line equal to `SIGN_COMMENT` (case-insensitive, surrounding punctuation/emphasis stripped) into the ledger with optimistic-concurrency `PUT`s, maintains one `<!-- ultralytics-cla -->` status comment, raises when anyone is unsigned, and re-runs the PR-head workflow after a successful `issue_comment` signature. Its dependencies are the PEP 723 block at the top of the file, locked in `actions/cla.py.lock`.
- `dependabot.py` (`ultralytics-actions-dependabot`; `dependabot/action.yml` runs `python -m actions.dependabot`) — scans every non-archived org repo's `.github/workflows/*.yml` and `action.yml` for `uses: owner/repo@ref`, resolves each action's latest stable release once (`get_latest_release` cache), updates SHA pins (with a `# vX.Y.Z` comment), major tags, and exact tags via `compute_update`, skips branch refs, and opens one Git-Data-API PR per `(action, new_ref)` on a `dependabot/github_actions/<slug>` branch unless an equivalent title is already open. Env: `GH_TOKEN`/`GITHUB_TOKEN`, `ORG`, `PUBLIC`/`PRIVATE`/`INTERNAL`.
- `github_report.py` (`ultralytics-actions-github-report`; `github-report/action.yml` runs `python -m actions.github_report`) — shells out to the `gh` CLI for repo listing, PR search, and merging. `run_pr_report()` writes the open-PR age report and, when `AUTO_MERGE_ACTIONS_PRS`, `auto_merge_actions_prs()` squash-merges (with `--admin --delete-branch`) at most one PR per repo whose title contains `bump` and `/.github/workflows`, whose author is `app/dependabot` or `UltralyticsAssistant`, whose files are all workflow/action files, and whose checks are all `SUCCESS`. Then `failed_scheduled_actions.run()` when `REPORT_FAILED_ACTIONS` (or the deprecated `REPORT_FAILED_SCHEDULED_ACTIONS`).
- `failed_scheduled_actions.py` (`ultralytics-actions-failed-actions`, alias `ultralytics-actions-failed-scheduled-actions`) — uses `urllib` directly (not `Action`) to report the latest failed default-branch run per workflow across the org within `REPORT_DAYS`; `parse_visibility` refuses to let a public repo inspect non-public repos.
- `dispatch_actions.py` — handles `issue_comment` PR comments containing `@ultralytics/run-ci`, `@ultralytics/run-all`, or `@ultralytics/run-docker` from org members: dispatches `ci.yml`/`docker.yml` (pushing a `temp-ci-<pr>-<ts>` branch for fork PRs and deleting it afterwards) and rewrites the comment with run links. It has no `[project.scripts]` entry and no `action.yml` step in this repo; only `tests/test_dispatch_actions.py` imports it.

### Composite sub-actions

- `retry/action.yml` — inputs `run`, `shell` (bash|python), `retries` (3), `retry_delay_seconds` (10), `backoff` (exponential|fixed), `jitter`, `timeout_minutes` (360). A `python3` supervisor runs the script in its own session, kills the process tree on timeout (exit 124; Linux uses `prctl` child-subreaper plus an env-token scan, Windows uses PowerShell), and re-runs with jittered delays that never round to 0. Behavior is covered only by `test-retry.yml`, not pytest.
- `setup-uv/action.yml` — wraps `astral-sh/setup-uv@v10.0.0` with `version: latest`, falling back to `latest-known` if that fails; inputs `python-version`, `activate-environment`, `enable-cache`, `cache-dependency-glob`, `ignore-empty-workdir`. Every other action here (including the root one) starts with `ultralytics/actions/setup-uv@main`.
- `cleanup-disk/action.yml` — removes `/opt/hostedtoolcache`, prunes Docker images, and drops swap files in parallel; no inputs.
- `dependabot/`, `github-report/`, `cla/` — build/install the package from `${{ github.action_path }}/..` (the action's own checkout), then run the module above with inputs mapped to the env vars listed there.

## Where to look

- Formatter output changed or a new formatter flag → the matching step in `action.yml` **and** the mirrored constant in `actions/format_code.py` (the `test_format_commands_match_action_yml` substring check accepts a `format_code.py` list that is a prefix of the `action.yml` one, so grep both); docs-specific prettier rules live in the "Run Prettier" step; codespell words in both `--ignore-words-list`s.
- Auto-format commit missing on a PR → the "Commit and Push Changes" conditions (fork PRs, the `github.actor != github_username` guard on `synchronize`, `.github/workflows/` always unstaged).
- Wrong model, provider, price, or prompt guidance → `actions/utils/openai_utils.py` (`*_MODEL_DEFAULT`, `MODEL_COSTS`, `SYSTEM_PROMPT_ADDITION`, `_get_default_model`, `get_review_model`); `README.md` and the `model`/`review_model` input descriptions in `action.yml` repeat the defaults and must be updated together (`test_default_models` pins them).
- PR review skipped, wrong verdict, or missing inline comments → `review_pr.main` gating, `post_review_summary` (APPROVE vs COMMENT rules), the comment validation block in `generate_pr_review`, and `parse_diff_files` for R/L line numbering; review prompt text is inline in `generate_pr_review`; tool behavior in `build_review_agent_tools`.
- Review sees stale or duplicated findings across pushes → `clear_previous_review`, `_build_review_history`, `_format_review_history`, and the `MAX_HISTORY_*` budgets.
- PR summary or labels on open → `first_interaction.main` and `get_pr_open_response`; on merge/close → `summarize_pr.main`; issue/discussion replies → `get_first_interaction_response`; label filtering → `filter_labels`.
- Files wrongly included in or excluded from AI diffs → `SKIP_PATTERN_STRINGS`/`should_skip_file`/`filter_diff_text` in `common_utils.py` (also used by the review `read_file`/`list_files` tools).
- Broken-link false positives in AI replies → `URL_IGNORE_LIST`, `URL_ERROR_LIST`, `REDIRECT_START_IGNORE_LIST`/`REDIRECT_END_IGNORE_LIST`, `BAD_HTTP_CODES`, `is_url`; the lychee step in `action.yml` is a separate checker for repository Markdown/HTML.
- Header not applied or applied to the wrong file → `COMMENT_MAP` (extension → comment style), `IGNORE_PATHS` (substring match on the repo-relative path), and the repo/`HEADER` gate in `update_file_headers.main`.
- Release not published → `should_publish` rules in `version_utils.py`, the actor gate in `publish.yml`, and remember `check` runs the PyPI-installed package.
- Adding a CLI command → module `main()`/`run()`, a `[project.scripts]` line in `pyproject.toml`, the `action.yml` step that invokes it with its env vars, and `tests/test_init.py::test_cli_entry_points` if it should be pinned.
- Adding a shared utility → put it in the owning `actions/utils/*.py`, export it from `actions/utils/__init__.py` (`__all__`), then import from `actions.utils`.
- Adding a composite action → `<name>/action.yml` + `<name>/README.md`, install via `setup-uv` and a wheel build of `${{ github.action_path }}/..` like `dependabot/action.yml`, and add a usage snippet to `README.md`.

## Gotchas

- `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `MODEL`, `REVIEW_MODEL` (`openai_utils.py`), `LABELS`/`SUMMARY`/`REVIEW`/`BLOCK_USER` (`first_interaction.py`), `CURRENT_TAG`/`PREVIOUS_TAG` (`summarize_release.py`), and `HEADER` (`update_file_headers.py`) are read at import time into module constants; setting `os.environ` after import (or in a test without reloading) has no effect — patch the module attribute (e.g. `patch("actions.utils.openai_utils.OPENAI_API_KEY", "x")`).
- Modules import names into their own namespace (`from .utils import Action, get_response`), so tests patch at the use site: `patch("actions.first_interaction.Action")`, `patch("actions.review_pr.get_agent_response")`, never `actions.utils.github_utils.Action`.
- `filter_diff_text` runs inside `get_pr_diff()`, so every consumer receives a `(diff_text, skipped_files)` tuple, never a string; `diff_text` may start with `ERROR:` for empty, oversized (406), or failed diffs and callers branch on that prefix.
- `generate_pr_review` prints the complete system and user prompts to the job log when `repository == "ultralytics/actions"` — expect very long logs on this repo's own PRs.
- `IGNORE_PATHS` in `update_file_headers.py` is a substring test: entries like `lock`, `env/`, and `build/` skip any path containing them (`.git/` carries a trailing slash so `.github/` is still processed).
- Codespell in `action.yml` skips `action.yml` itself, `*lock*`, `*translat*`, and `docs/??/*.md` translations; a misspelling inside those files is never flagged.
- The root `action.yml` `Checkout` step runs only for `pull_request` events, so on `pull_request_target` the reviewer has no local checkout: files come from the GitHub API and the `search_repo` tool is dropped.
- `Action` retries are for connection errors on every method but 5xx only on `GET`/`PUT`/`DELETE`; a failed `POST` (comments, labels, reviews) is not retried by the session — callers such as `cla._read`/`_persist` and `get_response` implement their own loops.
- `publish.yml`'s `check` job gates releases with the **PyPI-installed** `ultralytics-actions`, so a change to `version_utils.py` or `summarize_release.py` only affects the next release after it is itself published.
- `tests/test_update_markdown_codeblocks.py::test_main_real_files` and `update_markdown_code_blocks.main()` write a `temp_code_blocks/` directory in the cwd and delete it on completion; `format_bash_with_shfmt` only prints an error when `shfmt` is missing locally.
- The `Alert` label path in `apply_and_check_labels` rewrites the title/body, locks, and (for issues/discussions) closes the item as soon as the model returns `Alert` for a non-org member; `BLOCK_USER=true` additionally blocks the account org-wide.

## Tests

- `tests/` is flat, one file per module: `test_github_utils.py`, `test_openai_utils.py`, `test_common_utils.py`, `test_urls.py` (link parsing with `is_url` patched), `test_first_interaction.py` (also covers `review_pr`: history capture, tool construction against a real temporary git repo, APPROVE/COMMENT decisions), `test_summarize_pr.py`, `test_summarize_release.py`, `test_update_file_headers.py`, `test_update_markdown_codeblocks.py`, `test_format_code.py` (formatter constants vs `action.yml`, log-group discipline of every `run:` step), `test_cla.py`, `test_dispatch_actions.py`, `test_github_report.py`, `test_cli_commands.py`, `test_init.py` (version format, importability, entry-point names).
- No shared `conftest.py` or fixtures directory; each file builds `MagicMock` responses/events inline (`tests/test_cla.py` has small `response()`/`action()`/`ledger_response()` helpers worth copying). Network is always mocked (`requests.post`, `requests.Session.get`, `urllib.request.urlopen`, or the module-level function), so the suite needs no tokens or API keys.
- CI runs exactly `python -m pytest tests -v --cov=actions --cov-report=xml:coverage.xml` on Python 3.8 and 3.14; there is no Windows pytest job, no coverage threshold, and the composite actions are exercised only by `test-retry.yml` (retry) and by the org workflows that consume them.
